# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

KDP Studio is a CLI that generates Amazon KDP coloring books: an LLM invents the page scenes and book metadata, an image model draws black-and-white line art (one call per page), and a post-processing pipeline turns each image into a 300 DPI print-ready page.

The MVP spec, [docs/requirements.md](docs/requirements.md), is the source of truth for scope, decisions (D1–D10), functional requirements (FR-01–FR-13 and FR-17, stepwise generation, for the MVP; FR-09 and FR-11 are superseded by FR-17; plus post-MVP FR-14, a "This book belongs to…" page (`kdp-studio belongs-to`, or a step of `generate --belongs-to-page`), FR-15, the `kdp-studio cover` command (also the last step of `generate --cover`), FR-16, `kdp-studio price` for print cost, minimum list price and royalties, FR-18, a local ComfyUI image provider, FR-19, the target Amazon marketplace `--market`, and FR-20, a book parameter file `--config-file`), non-functional requirements (NFR-01–NFR-13), and the planned layout. Read it before implementing anything, and cite requirement IDs in commits and PRs. Its §0 tracks the implementation status of every FR and NFR (with PR numbers), and the same markers sit on the FR headings; update both when a requirement lands. The spec, README and user-facing CLI messages are in Polish. Profile keys are Polish too (`przedszkole`, `dorosli`, …), while image prompts and scene descriptions are in English.

Implemented so far: config loading (§7), input validation (FR-01, FR-02), idea generation (FR-03), image prompts (FR-04), raw image generation (FR-05), post-processing into print-ready pages (FR-06), idea review (FR-03a), book-level idea diversity (FR-03b), manifest and `canva.md` (FR-08), the AI-disclosure reminder (FR-13), the `profiles` command (FR-12), optional vision QA (FR-07, `--qa`) and stepwise generation (FR-17, which replaces resume FR-09 and dry run FR-11). Step 1 `ideas` writes `ideas.json`, `prompts.json` and `manifest.json` (pages `pending`); step 2 `images <dir>` generates the missing raw images into `raw/` (optionally QA, regenerating rejected pages from reserve ideas); step 3 `finalize <dir>` turns raw images into `svg/page_XX.svg` and full `page_XX.png` for Canva plus `canva.md`, with no API calls. `generate` runs all three. Cost tracking and the budget limit (FR-10, `--max-cost`) complete the MVP scope. Post-MVP FR-14 (`kdp-studio belongs-to`, the themed "This book belongs to…" front page, also a step of `generate --belongs-to-page` between images and finalize) is implemented too. FR-15 (`kdp-studio cover`) is implemented in three stages: geometry, KDP template check, layout, CMYK and the PDF; a model-coloured front with program-drawn titles; and a model-painted back/spine with a seam check, vision page selection, cover QA and optional back text. `generate --cover` runs it as the last step. The spec was revised for Canva (D9, FR-06, §7.4, §10.1): pages are full PNGs the user stretches over a Canva page, and Canva (not a script) assembles the interior PDF. `uv run kdp-studio generate …` makes real, paid OpenAI calls (one text call plus one image per page) when `OPENAI_API_KEY` is set; about $0.045 per image at `medium`, capped per run by `--max-cost` (default `max_cost_usd: 5.00`).

## Commands

```bash
uv sync                                    # create .venv with runtime + dev deps
uv run kdp-studio generate --theme "Dinozaury" --age przedszkole --style kawaii --format square
uv run kdp-studio ideas --theme "Dinozaury" --age przedszkole --style kawaii --format square   # step 1 only
uv run kdp-studio ideas output/<book> --redo idea_07,idea_19   # replace chosen ideas, same ids
uv run kdp-studio images output/<book> [--qa] [--image-quality low]   # step 2: missing/changed raw images
uv run kdp-studio finalize output/<book>                         # step 3: pages for Canva, no API calls
uv run kdp-studio belongs-to output/<book> [--qa] [--remove]    # FR-14 front page, after step 2
uv run kdp-studio profiles [age|style|format]   # list profile keys with descriptions (no API call)
uv run pytest                              # all tests
uv run pytest tests/test_validation.py::test_pages_out_of_range   # single test
uv run pytest --cov=kdp_studio --cov-report=term-missing
uv run ruff check . && uv run ruff format .
uv run mypy                                # strict, covers src/ and tests/ (configured in pyproject)
```

`KDP_STUDIO_CONFIG_DIR` overrides the config directory (default: `config/` at the repo root, resolved from the package path, so it assumes an editable install).

## Tooling notes (NFR-01, NFR-13)

- Python ≥ 3.12, `uv`, `typer`, Pydantic v2. Image stack, all prebuilt wheels with no native system libraries (NFR-11): Pillow, `opencv-python-headless` (Otsu, connected components), `potracer` (pure-Python potrace port, no `py.typed`, hence the mypy override in `pyproject.toml`) and `resvg-py` (SVG render).
- Typer ≥ 0.29 vendors click privately (`typer._click`); there is no `click` package. Use the public `typer.TyperException`, `typer.Exit` and `typer.Abort`.
- Ruff allows `–` and `×` (`allowed-confusables`) because Polish messages use them, and `docs/` is excluded from ruff.
- CI (`.github/workflows/ci.yml`) runs `uv sync --locked`, so after changing dependencies in `pyproject.toml` run `uv lock` and commit `uv.lock`. Lint and mypy run once; tests run on Linux, macOS and Windows with Python 3.12 and 3.14 (NFR-11). Pre-commit (NFR-13) is still missing.
- Secrets come only from env vars or `.env` (gitignored): `OPENAI_API_KEY`, later `GEMINI_API_KEY`. Keys must never reach logs or `manifest.json`. `.env` is loaded only in `cli.run()`, not in `main()`, so tests never pick up a real key. `describe_openai_error()` drops the provider message for 401s because OpenAI echoes a fragment of the key there.
- `openai` 3.x uses `httpx2` (not `httpx`); build test exceptions with `httpx2.Request`/`httpx2.Response`.

## Architecture (spec §8, §12)

Package: `src/kdp_studio/`. Existing modules:

- `config.py`: Pydantic models for every YAML file (`extra="forbid"`, so typos in config fail loudly) and `load_config()`, which raises `ConfigError`. Cross-file checks live in `AppConfig` (e.g. `allowed_ages` must name existing ages; each format's `safe_margin_in` ≥ `kdp_margins.outside_min_in`); `FormatProfile` checks `page_px == trim_in × dpi`. Formats have no `gutter_in`: the spine margin depends on page count, so it comes from the `kdp_margins` table in `settings.yaml` (`KdpMargins.gutter_in(pages_in_book)`), and a book thicker than the table is a FR-02 validation error.
- `models.py`: `BookSpec`, the validated input, plus `pages_in_book()`.
- `validation.py`: `validate_book_spec()` collects *all* input errors before raising `InputValidationError`, and returns warnings separately (KDP page minimum, style not meant for the age). Profile keys are checked here, not in `BookSpec`, because that needs the loaded config.
- `profiles.py` (FR-12): `format_profiles()` renders the `name` and `description` fields from the YAML, plus `allowed_ages` for styles and the default format (`cli.DEFAULT_FORMAT`, shared with `generate`).
- `cli.py`: typer app with an `ExitCode` enum. Entry point `run()` → `main(argv)`, which runs typer with `standalone_mode=False` so usage errors (bad type, unknown flag) exit with 1 instead of typer's default 2, which §9.3 reserves for partial results. Tests call `main([...])` directly; `tests/test_cli.py` has an autouse fixture that swaps `cli.create_text_provider`/`cli.create_image_provider` for `FakeTextProvider`/`FakeImageProvider`, makes `cli.create_vision_provider` fail (tests opt in with `_vision()`), and `chdir`s to `tmp_path`. Both providers are created, and the format's aspect checked against `supported_aspects()`, before the first API call. Commands `ideas`, `images`, `finalize` and `generate` share `_step_ideas`/`_step_redo`/`_step_images`/`_step_finalize`; each step runs under `_locked(book_dir)` (`BookLock`), and `generate` creates every provider before the first API call and holds one lock for all three steps. `tests/test_steps.py` covers FR-17 and imports the autouse fixture from `tests/test_cli.py`.
- `providers/base.py`: `TextProvider` (`complete_json(system, user, schema) -> (parsed, Usage)`) and `ImageProvider` (`supported_aspects()`, `generate(ImageRequest) -> ImageResult`) protocols, `Usage`, `png_dimensions()`, and `ProviderError(message, fatal=True)`. `fatal` decides scope: fatal (bad key, `insufficient_quota`, unknown model) stops the whole run with exit 4; non-fatal (`moderation_blocked`, transient errors after retries, bad payload) fails one page. `providers/registry.py` maps the names in `settings.yaml` (`providers.text`, `providers.image`) to lazily imported classes. Shared OpenAI pieces (client without SDK retries, error text, retry and fatal classification) live in `providers/openai_common.py`. `providers/openai_text.py` uses `client.responses.parse(..., text_format=schema)` with the SDK's own retries off (`max_retries=0`), because the SDK also retries permanent 429s such as `insufficient_quota`. Retries go through `providers/retry.py` (`call_with_retries`, 3 attempts, exponential backoff or `Retry-After`); each adapter supplies the transient/permanent decision (`openai_retry_decision`). `providers/openai_image.py` calls `images.generate(..., n=1, output_format="png", background="opaque")` (opaque, because transparency would turn black in FR-06) with exact-aspect custom sizes from `SIZES` (3:4 → 1152x1536; the model accepts multiples of 16), and decodes `data[0].b64_json`. `providers/fake.py` has `FakeTextProvider` (canned responses) and a thread-safe `FakeImageProvider` that returns real tiny PNGs from `make_png()`.
- `pipeline/postprocess.py` (FR-06): `PostProcessor` protocol and the chain `Grayscale → Threshold (Otsu or the age profile's fixed value) → Despeckle (min_speck_area) → VectorizeAndRender → Rethreshold`. `VectorizeAndRender` traces with `potracer`, writes the archive `svg/page_XX.svg` (SVG 1.1, one `evenodd` path, source pixel size) and renders a page SVG with `resvg-py`, with the trace scaled into `PageGeometry.content_box` and clipped to it (potrace curves can overshoot the source by a fraction of a pixel, which lands in the margin after scaling). `page_margin_in()` = `max(safe_margin_in, outside_min_in, gutter_in(pages_in_book))`, computed once per book and applied symmetrically. `verify_page()` enforces NFR-07 after saving (exact `page_px`, mode L without alpha, 300 DPI, only 0/255, black pixels inside the content box, not blank); a failure fails that page. One letter page takes ~2.5 s (NFR-05 allows 5 s); `potracer` holds the GIL, so post-processing does not speed up with `--concurrency`.
- `pipeline/worker.py` (FR-05, FR-17 step 2): `PageWorker.run(jobs)` uses a thread pool (`concurrency`) and writes only `raw/<name>.png` atomically; final pages are step 3's job. With QA, the optional `preview` `PagePostprocessor` renders the page into a temporary directory so QA judges print output. Page names come from `page_name()` (`page_07`, or `page_007` when the book has 100+ pages) so alphabetical order is page order for Canva (FR-08). A fatal `ProviderError` sets a stop flag inside the worker thread, so a free thread cannot pick up another page before the main thread cancels the queue; pages already in flight finish. `page_jobs()` takes the first `pages` prompts; the rest are the QA reserve. CLI exit: 4 on a fatal error, 2 if any page failed.
- `pipeline/ideas.py` (FR-03): `build_prompts()` assembles the English prompt from the age/style/format profiles. The LLM-facing schema (`_LLMIdeas`) deliberately has no min/max constraints; `IdeaGenerator` enforces them afterwards: it drops empty and verbatim-duplicate ideas, assigns ids `idea_01…` itself, trims to `pages + ceil(pages * reserve_ratio)`, dedupes keywords and caps them at 7. A short reserve is a warning; fewer ideas than pages, or invalid metadata, triggers one retry, then `ProviderError`.
- `pipeline/prompts.py` (FR-04): `PromptBuilder(spec, config)`. Each prompt is `Scene: <scene>.` followed by `style_block`, which is identical for every page of a book: style `prompt_fragment`, age `prompt_fragment`, format `composition_hint` and `FIXED_CONSTRAINTS` (the spec's list, verbatim; a test pins it). Prompts are built for reserve ideas too and saved to `prompts.json` until the manifest (FR-08) exists.
- `pipeline/idea_review.py` (FR-03a, added to the spec in this repo): `IdeaReviewer.review(spec, ideas, generator)` makes a separate LLM call with a reviewer prompt and a checklist; each idea gets `ok`, `revise` (reviewer returns the corrected title/scene/elements) or `reject` (reason in Polish). Rejected ideas are replaced by topping up via `IdeaGenerator.generate_more()` (max 2 rounds) so the reserve stays full; ids are renumbered `idea_01…` at the end and the trail goes to `ideas.json` → `review`. Fewer accepted ideas than pages raises `ProviderError` (exit 4). On by default (`review_ideas` in settings, `--no-review-ideas`). `THEME_RULE` in `pipeline/ideas.py` is shared by the generation and review prompts. Calibration matters: a stricter first version revised 48 of 60 real ideas, mostly by adding the same Christmas tree, so the reviewer prompt tells it to leave passing ideas alone and vary added elements. `FakeTextProvider.routes` answers by schema class name (`_Review`, `_LLMMoreIdeas`), and `tests/conftest.py` has `review_response()`/`approve_all()`.
- `pipeline/diversity.py` (FR-03b): every idea carries scene tags from the LLM (`subject`, `characters`, `action`, `setting`, all optional on `PageIdea` so older files load), and code, not the model, measures the book pages (first `pages` ideas) against limits: `multi_subject_share` from the age profile (also the target in the generation prompt via `cast_rule()`) and `max_action_share`/`max_setting_share`/`max_element_share` from `settings.yaml` `diversity`. Elements are counted by `noun()` (last word, singular) minus the main subject. `theme_anchors` (returned by the generator, e.g. `kitchen` for "Kotki w kuchni") are exempt. `IdeaReviewer.review()` ends with `swap_with_reserve()` (no API call) and, only if issues remain, one `_Balance` LLM call whose revisions are accepted one by one only if they are candidates, not duplicates, and lower `total_excess()`. The report goes to `ideas.json` → `diversity`; leftover issues are warnings. Without review the CLI only measures. Synonyms (`tree`/`evergreen`) count separately, so limits are lenient. Test fakes: `llm_ideas_response()` gives every second idea two characters and unique elements so it passes the limits; `scene_tags()` builds the tag fields; `FakeTextProvider.routes["_Balance"]` answers the balancing call.
- `pipeline/manifest.py` (FR-08, FR-17): `ManifestWriter.start()` (step 1) writes `manifest.json` with status `ideas_ready` and every page `pending`; `load()` reads it back (`ManifestError`, exit 1). Page status is `pending` → `raw_ok` (step 2, `record_raw()` from the worker's `on_done` callback on the main thread, so no lock) → `ok` (step 3, `record_final()`), or `failed`. Pages store `prompt_sha256` and `raw_sha256` of what was generated, `final` (`raw_sha256` + `postprocess_sha256`) of what was finalized, the user-set `action` (`regenerate`, cleared after use), `edited_by_user` and `quality`. `update_status(fatal)` derives the book status: `failed`, `completed`, `partial` (pending/failed pages) or `raw_ready`. Paths are relative to the book directory. Costs (FR-10): `record_raw(cost_usd=…)` adds to the page's `cost_usd` and the book total `Manifest.cost_usd` (accumulated across runs), `add_ideas_cost()` covers `--redo`, `ideas.cost_usd` the text calls; `update_status(budget_error=…)` sets `budget_exceeded`. `pipeline/canva.py` renders `canva.md` (§10.1) from the manifest, with a page-order table and a warning listing missing pages; it is written by step 3 only. `AI_DISCLOSURE` (FR-13) is shared by the manifest, `canva.md` and the console summary.
- `pipeline/qa.py` (FR-07): `QAChecker(vision, spec, config, ideas).check(png, idea_id)` sends the finished page (after FR-06, i.e. what gets printed) with `QA_INSTRUCTIONS`: the spec's criteria as `Criterion` codes (`panels`, `shading`, `text`, `open_contours`, `detail_level`, `scene_mismatch`, `other`), the age profile's `line`/`subjects`/`background`/`fill_areas` and the idea's scene; issue details come back in Polish. The LLM schema uses `passed` (`pass` is a keyword); `QAResult` serializes as `{"pass", "issues"}` via alias (needs pydantic ≥ 2.11). Calibrated on real pages: good pages pass, a 2×2 grid, added text and a wrong scene are rejected; ~3.6k input tokens per page with `detail: "high"`. `providers/openai_vision.py` is the adapter (`responses.parse` with an `input_image` data URL; a refusal is non-fatal). With QA on, `PageWorker.generate_page` loops: raw image → preview → QA → on rejection move the raw PNG to `rejected/<name>_tryN.png` (an empty `raw/` slot makes the next `images` run regenerate the page), take the next idea from the shared, thread-safe `ReservePool`, retry (at most `qa_max_retries`, default 2). `PageOutcome` carries the final `idea_id`/`prompt`, `attempts`, `qa`, `qa_usage` and `rejected`; the manifest stores them per page. A non-fatal QA error fails the page; QA is off by default (`qa` in settings, `--qa/--no-qa`), and the vision provider is only created when it is on.
- `pipeline/output.py`: `book_dir()` (FR-08 naming, Polish letters transliterated by `slugify`) and `write_json_atomic()` (temp file + `os.replace`). `ideas`/`generate` refuse an existing `ideas.json` and point to the step commands.
- `pipeline/book.py` (FR-17): no API calls, only plans from files. `BookLock` (`.kdp-studio.lock`, `O_EXCL`; removes the book dir again if it created it and nothing else was written). `load_ideas()` and `check_assignment()` validate the user-edited `ideas.json` and page→idea mapping before any image (exit 1). Until the first image (`never_generated`), `sync_order()` maps pages to the first ideas in `ideas.json` order; afterwards the manifest's `idea_id` rules. `plan_images()` queues pages with `action: regenerate`, no accepted raw, `failed` status or a changed prompt hash (so editing a profile's prompt fragment regenerates every page); `user_edits()` detects hand-replaced raw files by hash and the CLI marks them `edited_by_user`. The QA reserve is unassigned ideas minus ones QA already rejected. `plan_finalize()` picks pages whose `final` hashes differ from the raw file or `postprocess_sha256()` (age params + geometry); a finalize error keeps `final`, so the same inputs are not retried.
- `IdeaReviewer.replace()` (FR-17 `--redo`): `generate_more()` + review of only the new ideas (accepted = the rest of the book), up to `max_topups + 1` rounds, then the new ideas take the old ids; replaced ideas go to `review.rejected` with reason `zastąpiony (--redo)`. `redo_hints()` (diversity.py) turns the rest of the book into prompt hints for `generate_more(hints=…)`: avoid values already at their limit, add multi-character scenes if short. The shared verdict handling is `IdeaReviewer._apply()`.
- `observability.py` (NFR-09): `book_log(book_dir, level)` attaches a JSON-lines `FileHandler` (`JsonFormatter`) for `kdp-studio.log` (`LOG_FILE` in `pipeline/output.py`) to the `kdp_studio` logger only, so SDK/HTTP logs never reach the file (NFR-10); a `NullHandler` keeps events silent when no book log is open. Log with `log_event(logger, level, event, **fields)`. CLI `_locked(target, log_level)` opens the log for the step; `BookLock.release` still removes a dir it created when only the log is left. `LoggedTextProvider`/`LoggedImageProvider`/`LoggedVisionProvider` wrap the providers in the CLI and log every call at debug (`api_call`: duration, tokens, image prompt) and every `ProviderError` at warning. `retry.py` logs `retry` with the error type only. `StepTimer` + CLI `_timed()` log `step_start`/`step_end` and print `Czas kroku (…)`; `generate` prints `Czas: …; razem …` and logs `run_end`. `progress_bar()` draws a transient rich bar on stderr only in a terminal (Live redirects stdout/stderr, so per-page lines print above it) and is a no-op elsewhere, so tests see no bar. `--log-level info|debug` on every step command, default `log_level` in settings.
- `pipeline/cost.py` (FR-10): `usage_cost(ModelPrice, Usage)` from `settings.api_pricing` (USD per 1M input/output tokens, copied from the provider's pricing page with `source`/`checked`; cached tokens are priced in full). `CostTracker(pricing, limit_usd)` sums the cost of one command run by kind (`ideas`, `images`, `qa`) under a lock; `over_budget()` is `spent >= limit`. CLI `_cost_tracker()` fails with exit 1 before any API call if a model has no price or `--max-cost` ≤ 0. `PageWorker.over_budget` is checked before every new page and before a QA reserve retry (no retry then: the page fails); `PageWorker.on_spent` runs in the worker thread right after a page, so the CLI adds its cost before that thread takes the next page (other threads' pages in flight can still overshoot). `ImagesResult.budget_exceeded` → status `budget_exceeded`, exit 3; `generate` then skips finalize, and stops before images if the ideas alone exceed the limit. Tests price the fake models via `tests/conftest.py` `fake_settings()`/`FAKE_PRICES` (config files are replaced wholesale, so use `fake_settings(qa=True)` rather than `{"qa": True}`).
- `pipeline/belongs_to.py` (FR-14, `kdp-studio belongs-to`): the image model draws only a themed frame around an empty plaque (`belongs_to_prompt()`: `belongs_to_page.composition` + the most common subject and elements of the book pages + the book title, then the pages' style block with `FRAME_CONSTRAINTS`, i.e. `FIXED_CONSTRAINTS` minus `no frame`). `BelongsToMaker.make()` (after the pages' step 2) renders each attempt in a temp dir and checks the ink in `text_box` (fractions of the content box, `PageGeometry.area()`) against `max_ink_ratio`, then optional QA (`QAChecker.check_belongs_to()`, criteria `text`/`scene_mismatch` swapped via `{text_rule}`/`{scene_rule}` in `QA_INSTRUCTIONS`); rejected tries go to `rejected/front_belongs_to_tryN.png`; after `max_retries` it copies the first ready page's raw image into `raw/front_belongs_to.png` with layout `fallback` (`book.fallback_art()`). `BelongsToRenderer.render()` runs the normal chain (fallback: `PageGeometry.with_art()` puts the art in the top `fallback_art_height`; `art` is `repr=False`, so page hashes did not change) and `draw_text_block()` writes the text with the bundled Fredoka OFL font (`assets/fonts/`, `font_variation`), shrinking it to fit, outline letters per age `belongs_to.outline_text`, plus the name line, then `verify_page()`. Manifest: `front_matter.belongs_to` (`FrontPage`: page-like fields + `layout`, `fallback_source`, `elements`), `record_front_raw()`/`record_front_final()`, counted in `update_status()`; `book.plan_front()` (a new frame only for `action: regenerate`, a missing raw, a failed try or a changed prompt; a failed text render with a current raw is not retried with a new frame)/`front_needs_finalize()`; `_front_params_sha256()` covers postprocess params, age `belongs_to`, text settings, the font file hash and the layout. The CLI command `belongs-to` (`_step_belongs_to()`) does the whole page under the book lock: it creates the manifest entry, generates the frame when `plan_front()` says so (exit 3 if already over budget, 4 on a fatal error), renders the text (`_finalize_front()`, no API call when only text/font settings changed), refreshes `canva.md` if step 3 already wrote it, exit 2 if the page failed; it needs a ready raw page (`_belongs_to_blocker()`, exit 1). `--remove` deletes the PNG/SVG and the entry but keeps the raw image. `generate --belongs-to-page` runs `_generate_belongs_to()` between images and finalize (skipped with a warning when no page is ready). `images` and `finalize` no longer touch the page: `images` warns when it regenerated the fallback source, `finalize` warns when the page is missing or stale. `canva.md` places `front_belongs_to.png` as front-matter page 2. A missing font is exit 1 before any API call. Tests: `tests/test_belongs_to.py` (`FrontAwareProvider` answers frame prompts with a blank or busy plaque).
- FR-15 `kdp-studio cover <book>`, stage 1 (no model calls): `pipeline/cover_geometry.py` (`CoverGeometry` from `manifest.layout` + `settings.kdp_cover`: spine = `pages_in_book × paper_factor_in`, trim/fold/live/key zones and the barcode box in inches from the top-left of the bled cover, `px()` at the book DPI; `check_template_name()` parses `PAPERBACK_<w>x<h>_<pages>_BW_WHITE_…`, `measure_template()` reads the KDP template by colour with `cv2.inRange` (`cover.template_colors`, calibrated on `tests/fixtures/kdp_templates/*.expected.json`), `compare_template()` within `template_tolerance_in`). `pipeline/cover.py` lays out `CoverLayers` (`color` RGB through the ICC profile, `black` L = K100, `paper` L = K0): front sketch (title/subtitle with Fredoka Bold via `pipeline/fonts.py` `load_font()`, the chosen page's line art below), back thumbnails in frames sized from `line_width_px()` (distance transform) above the barcode, spine title from `max(spine_text_min_pages, spine_text_kdp_min_pages)` pages; `check_placements()` asserts zones and the barcode. `pipeline/cmyk.py`: `IccConverter` (ImageCms; `CmykError` → exit 1 with where to get SWOP), `NaiveConverter` for tests, `compose_cmyk()` (ink limit on CMY only, then K0 paper and K100 black), `gamut_map()` (ΔE76). `pipeline/pdf.py` writes the one-page DeviceCMYK Flate PDF by hand with `TrimBox`/`BleedBox`, no ICC/`OutputIntent`. CLI `cover` (`cli.cmyk_converter` is the test seam) records `manifest.cover` (`CoverInfo`); `images` warns when cover pages were regenerated. Stage 3: `pipeline/cover_vision.py` holds the three vision calls: `contact_sheet()` (numbered thumbnails drawn by the program) + `propose_pages()`/`choose_pages()` (invalid model picks fall back to the default with a warning; manual `--cover-page`/`--thumbnails` stay fixed, manual thumbnails are left off the sheet), `analyze_front()` (horizon + left-edge band colours) and `check_cover()` (`--qa`, criteria `text`/`front_mismatch`/`style_mismatch`/`other`, `CoverQAResult` serialised as `{pass, issues}`). `pipeline/cover_back.py` `BackPainter` (the `paint_back` callback of `build_cover()`, called with the flattened coloured front) builds `back_prompt()` from `cover.back_prompt` (placeholders `{horizon}`, `{colors}`, `{spine_pct}`, `{margin_pct}`, validated in config), sends the front as `reference_image` for the back+spine aspect, then `align_to_front()` warps the back vertically so its Lab row profile next to the spine matches the front's left edge (DTW within `seam_align_max`, one smoothed row map for the whole width, so baselines stay straight; the model ignores the horizon height in the prompt), then `seam_check()` compares median band colours (`seam_bands`, ΔE in Lab via cv2) of the strips on both sides of the spine/front fold, skipping rows within `horizon_tolerance` of a detected horizon (`pixel_horizon()`; a 3% shift would otherwise swap sky for grass in a band), plus the horizon positions; it retries up to `max_retries`, keeps the best try with a warning if none passes, and `blend_seam()` ramps the last `seam_band_in` of the spine side into the front's left edge. The back is painted only when the front was coloured, before `back_text` and titles are drawn (they live in the colour layer); thumbnails stay white through the K0 paper layer. `layout_back_text()` fits the most sentences of the book description into `back_text_max_height` of the back zone at `back_text_pt`→`back_text_min_pt`, and thumbnails move below it. Post-MVP FR-19 (spec only): `--market US|UK|DE|…` on `ideas`/`generate` (default `default_market: US`, stored in the manifest) picks the Amazon marketplace, not just a language: metadata (title, subtitle, description, keywords) in that locale's spelling and search terms, replacing `metadata_language`; image prompts stay English. `config/markets.yaml` is the single source per marketplace: locale, currency, FR-16 print costs and royalty thresholds (EU markets share a `pricing_group`) and `terms` the program draws itself (FR-14 text, cover subtitle, ages phrase); fonts must cover the market's characters (exit 1 otherwise). Post-MVP FR-20 (spec only): `--config-file <book.yaml>` on `ideas`, `generate`, `images`, `belongs-to` and `cover`. One Pydantic schema (`BookInput`, `extra="forbid"`) serves the file and the manifest's `input`: top-level keys are `generate` flag names in snake_case, `belongs_to:` and `cover:` sections hold their own options (`enabled` = `--belongs-to-page`/`--cover`, `cover: true` is shorthand). Precedence: CLI flag > file > profile > `settings.yaml` > code default; a list from a flag replaces the file's list. Unknown keys fail with exit 1 and the key path; relative paths in the file resolve from the file's directory; no secrets in the file. A `manifest.json` is accepted (its `input` is read), so an existing book can seed a new one. On `images`/`belongs-to`/`cover`, book-defining keys must match the manifest (exit 1 otherwise). The manifest stores the effective merged `input`, plus `config_file` (path, sha256) and `overrides`. Typer options must default to `None` so a missing flag is distinguishable; today's signature defaults for `--format`, `--pages`, `--strict` and `--output-dir` move into the merge step. Post-MVP FR-18 adds `ComfyUIImageProvider` (`--image-provider comfyui`): a ComfyUI server on the LAN, the user's API-format workflow in `config/comfyui/` with `{{positive}}`/`{{negative}}`/`{{seed}}`/`{{width}}`/`{{height}}` placeholders, generation capped at 512 × 512 or 768 × 512 px (an upscale node in the workflow may enlarge the output), `POST /prompt` → poll `/history/{id}` → `/view`, concurrency 1, cost 0. It needs `ImageRequest` to carry the prompt structure (scene, style parts, negatives) so Stable Diffusion gets a short positive prompt (CLIP reads ~77 tokens) and a real negative prompt, while the OpenAI adapter keeps building today's prompt verbatim. Spec §14a lists post-MVP ideas (`--humanize`, `--character`, `--scenes`) that are not requirements yet. Never ask the image model to draw text (FR-14 overlays it in code). Also post-MVP: the paperback cover (FR-15, `kdp-studio cover <book_dir>`, built, see above). Books are always paperback, black-and-white interior on white paper, so the paper factor (0.002252"), bleed and zones are fixed values in `settings.yaml` `kdp_cover`, not CLI options; hardcover, cream paper and colour interiors are out of scope. Cover geometry (spine = `pages_in_book × paper_factor`, bleed, fold lines, safe zones, the 2 × 1.2" barcode box) is computed from KDP formulas (D10), never read from the KDP template by an LLM; the optional template PNG is parsed by pixel colour only to cross-check and draw the preview. The front is the chosen page colorized via `reference_image` with crisp 300 DPI lines overlaid and the title drawn by the program; back + spine are generated together in one call with the front as reference, matching its horizon, then the seam at the spine/front fold is checked (ΔE) and blended on the spine side. Back thumbnails (≥ 3) get frames thicker than their scaled line width and are placed by the program outside the barcode box. `cover.pdf` is CMYK: everything is composed in RGB, the colour layer is converted once through the configured ICC profile (`cover.cmyk.profile`, Pillow `ImageCms`, not bundled if its licence forbids redistribution), black lines, frames and black text are drawn directly as K100 after conversion, total ink is capped (`max_total_ink_pct`, CMY reduced, K kept), and `cover_proof.png`/`cover_gamut.png` soft-proof the colour shift before upload; `cover.png` and `front.png` stay RGB. KDP recommends CMYK but names no profile or ink limit and strips embedded colour profiles, so the PDF is plain `DeviceCMYK` with no ICC profile and no `OutputIntent` (hence not PDF/X-1a); the profile used is recorded only in the manifest. Also post-MVP: pricing (FR-16, `kdp-studio price`). KDP's black-ink paperback print-cost tables and royalty thresholds per market live in `config/kdp_pricing.yaml` with source URLs and a `checked` date (not scraped). Print cost is a flat fee up to 110 pages (AU 108), else fixed + pages × per-page; both our formats are large trim. Minimum list price = print cost / royalty rate (50% up to the market threshold, e.g. 9.98 USD, else 60%), rounded to the nearest cent like KDP's calculator.

Flow (FR-17): step 1 `CLI → BookSpec (validation) → IdeaGenerator → IdeaReviewer → PromptBuilder → Manifest (ideas_ready)`; step 2 `Manifest + ideas.json → plan_images → PageWorker × concurrency (ImageProvider → optional preview + QAChecker) → raw/`; step 3 `plan_finalize → PagePostprocessor chain → page_XX.png + canva.md`.

Invariants the design depends on:

- **Provider isolation.** `pipeline/` depends only on the `Protocol` interfaces in `providers/base.py` (`TextProvider`, `ImageProvider`, `VisionProvider`, `PostProcessor`). Implementations are chosen from config through a registry (`providers.image = "openai"`). The pipeline must never import a vendor SDK (enforced by `tests/test_architecture.py`). A new provider (Gemini is next) means one new adapter file plus a registry entry, with no changes in `pipeline/`. `ImageRequest.reference_image` is in the contract from day one, even though the OpenAI adapter ignores it in the MVP.
- **One API call = one image** (D4). Never ask a model for several pages in one call, because it starts producing grids and collages. Series consistency comes from a shared style block that is identical across every page prompt (FR-04), plus fixed negative constraints (`no grid, no multiple panels, no collage, no text…`).
- **All ideas in one LLM call** (D5, FR-03). Structured output covering the book metadata plus `pages + ceil(pages * reserve_ratio)` ideas, so the model can keep scenes distinct. The extra ideas are the reserve used when QA rejects a page.
- **Profiles are data, not code** (§7). Age, style, and format profiles in `config/{ages,styles,formats}.yaml` drive both prompt fragments and post-processing parameters (e.g. `min_speck_area`, potrace smoothing, which differ for thick toddler lines and fine adult line work). Quality tuning must not require Python changes. Defaults live in `config/settings.yaml`; CLI flags override them.
- **Post-processing chain** (FR-06): grayscale → threshold (Otsu by default) → despeckle → potrace to SVG (`svg/`, archive only) → render to the full `page_px`, fitted and centred inside a symmetric margin of `max(safe_margin_in, outside_min_in, gutter_in(pages_in_book))` on every side (gutter from the KDP table in `settings.yaml` `kdp_margins`, spec §7.4; computed once per book), opaque white, no bleed → re-threshold to remove anti-aliasing greys → `page_XX.png` as 8-bit grayscale (mode `L`, values 0/255 only, no alpha, 300 DPI). Vectorizing instead of upscaling is deliberate (D6), since models return roughly 1–1.5k px and pages need 2550+ px. Each output is checked automatically for exact `page_px`, 300 DPI metadata, mode `L` with only 0/255, and content-area fit (NFR-07).
- **Canva assembles the PDF** (D9). The user uploads the `page_XX.png` files to Canva and stretches each one over a full page, so every PNG must be a complete page with margins baked in. Canva gets PNG, not SVG (Canva's SVG limits: < 3 MB, 150–200 px wide, SVG 1.1). Page numbers are zero-padded so alphabetical order matches page order, the book root holds no other PNGs except optional `front_*.png` front-matter pages (FR-14), and each book gets a `canva.md` with assembly steps (FR-08, spec §10.1).
- **Manifest as checkpoint** (FR-08–FR-10, NFR-04). `manifest.json` is written incrementally after every page, atomically (temp file, then rename). Re-running a step (FR-17) does only the missing work: `images` regenerates only pages that are not done or that the user marked, and never re-calls the idea LLM. Each API call records its cost, and `--max-cost` stops new work once the budget is exceeded.
- **KDP page math** (FR-02, D8). Single-sided printing means `pages_in_book = pages * 2 + front_matter_pages`, and KDP's paperback minimum is 24. `pages_in_book` also selects the gutter margin from KDP's table (24–150: 0.375", 151–300: 0.5", 301–500: 0.625", …), so the gutter is not a format property. `gutter_in` is still declared in `config/formats.yaml` and `config.py` and must move to `settings.yaml` `kdp_margins` (spec §7.4) when FR-06 is implemented.
- **Exit codes** (§9.3): 0 success, 1 validation or config error, 2 partial (missing `ok` pages), 3 budget exceeded, 4 provider error after retries.

## Testing approach (NFR-03)

Unit tests run offline against fake providers (`providers/fake.py`, where `FakeImageProvider` returns prepared PNGs). Post-processing is tested against golden image files. The target is ≥ 80% pipeline coverage.

## Output

Generated books go to `output/<theme-slug>_<age>_<style>_<format>/` (gitignored), containing `manifest.json`, `ideas.json`, `canva.md`, `kdp-studio.log` (NFR-09), `page_XX.png` (full pages for Canva), `svg/` (archive), `raw/`, and `rejected/`.
